# Production audit — 2026-09-16

## Architecture

- **Frontend:** Vite + React 18 SPA with React Router, Tailwind, React Query and Zustand. It is not Next.js; public content is client-rendered and lacks SSR/SEO metadata routes.
- **Backend:** JavaScript Express modular monolith using Mongoose, cookie JWTs, Cloudinary and Razorpay SDK (not yet wired into an order flow).
- **Database:** MongoDB models exist for users, admins, products, categories, carts, orders, announcements and reports. Only user/admin/category/product/cart/profile operations are partly routed.
- **Auth:** Separate user and admin collections; JWT cookies are HTTP-only, expiry is 30 days. Authentication middleware loads the actual record and checks status.
- **Media:** Admin product uploads use in-memory Multer validation and Cloudinary. Cloudinary public IDs are retained.
- **Deployment:** Not configured. There are no Render/Vercel manifests, production environment validation, monitoring, database backups, or CI.

## Findings

| Severity | Finding | Root cause | Required fix |
|---|---|---|---|
| Critical | Checkout cannot create orders or charge payments | No checkout/order/payment routes or services | Implement server-authoritative checkout, stock transaction, Razorpay order/verification/webhook and idempotency |
| Critical | Storefront uses static data while admin writes MongoDB products | `client/src/data/products.ts` is disconnected from API | Add public catalog API, switch list/detail/cart to it, remove static production catalog |
| High | Admin panel has fake sections | Routes return `data: []`; client shows placeholders | Build dashboard aggregations, sales/orders, feedback and announcements or remove unshipped navigation |
| High | No backend product update or category CRUD | Admin only creates/deletes products; category API is read-only | Add validated admin CRUD with archive policy and category-reference safeguards |
| High | Order schema lacks immutable snapshots and shipping structure | `Order.products` references product and only stores a numeric price | Snapshot name/SKU/images/pricing/address; never rely on mutable product records for history |
| High | Client cart is not the secure server cart | `useCart` stores local/static objects; `/api/cart` is unused | Reconcile authenticated cart, validate every line server-side at checkout |
| High | Input validation is inconsistent | Profile, query params, user search, category/product routes use manual/loose checks | Define server DTO validation for every body, query and parameter |
| Medium | API client contract is inconsistent | Several pages still hardcode `http://localhost:5000` instead of `src/lib/api.ts` | Migrate all calls to one typed API client and standardized error envelope |
| Medium | User/product pagination is unbounded | `limit` query accepts arbitrary values; deleted product list has no pagination | Clamp page/limit and apply projections/indexes |
| Medium | Mongo regex search is unescaped and unbounded | Admin user `search` is put directly into regex | Escape search input, limit length and add appropriate indexed search strategy |
| Medium | No structured audit/security logs | Controllers use direct `console.error` | Add request ID and structured redacted events for auth/admin/order failures |
| Medium | No automated backend tests | `server` test script deliberately fails | Add unit/integration API tests using an isolated database |
| Low | Dead code remains | `seedCategories` is unreferenced; Announcement/Report models are unexposed | Remove or implement only when corresponding feature is built |

## Security verification

- Unauthenticated protected routes return 401 through `requireUser` / `requireAdmin`.
- User/admin JWT types are separated and admin routes are protected server-side.
- CORS restricts configured origins and cookie mutations require an allowed browser Origin.
- Login rate limits, request body limits and product upload MIME/size restrictions exist.
- Remaining risks: no CSP tailored for Google/Razorpay/Cloudinary, no CSRF token strategy, no JWT revocation/rotation, weak password policy (minimum six characters), no password reset/verification, and no webhook verification.

## Course/career search

No `course`, `career`, `courses`, or `careers` routes, API handlers, or navigation matches were found in `client/src` or `server/src`.

## Scalability assessment

20,000 registered users is achievable with an Atlas replica set and stateless Render instances, but this code has not been load-tested and is not ready to claim a concurrent-user number. The immediate bottlenecks are static-client/server catalog divergence, unbounded admin queries, missing checkout transactions, and lack of caching/CDN deployment configuration. Image traffic should remain on Cloudinary; application-level DDoS protection requires a CDN/WAF in front of the host.
